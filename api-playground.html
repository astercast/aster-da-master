✦The API playground

Touch the archive

Every record on this site is a versioned JSON document. Pick an endpoint, read the live response, copy what you need. Agents start at api/v1/index.json. The operator's manual is AGENT.md (base URL pattern, key endpoints, end-to-end workflows); the browsable agentic surface is agents.html; conventions live in API.md.

deep-cuts-finder

Surface the vault's quietest-play tracks for playlists and deep listening.

  1. GET api/v1/sessions.json — flatten sessions[].tracks into one list.
  2. Sort ascending by plays; take the bottom N (median vault track ≈ 450 plays).
  3. GET api/v1/codex.json — match title words to families for a playlist theme.

session-archaeology

Reconstruct one of the 61 sessions: when it happened, what came out, who was in the room.

  1. GET api/v1/sessions.json — find the session by id; read span, tracks, plays.
  2. GET api/v1/circle.json / api/v1/scene-figures.json — resolve title credits.
  3. GET api/v1/codex.json — cross title words against the 16 families.
  4. GET api/v1/artist.json — place the session in eras[].

collaborator-tracer

Map a collaborator's footprint: tracks, plays, years active, verified research notes.

  1. GET api/v1/circle.json — look up the slug; read shared_transmissions, shared_plays, tracks[].
  2. If absent, GET api/v1/scene-figures.json — producers live here by rule.
  3. Read verified_notes (research pass 2026-10-11) and cite the sources.
  4. GET api/v1/artist.json — map years_active onto eras[].

milestone-watcher

Watch vault tracks approaching round-number play counts.

  1. GET api/v1/milestone-watch.json — read summit and each bands[] entry.
  2. Sort approaching tracks by needed ascending — smallest needed is closest.
  3. State the plays_snapshot date (2026-10-11) in every report.

era-briefing

Summarize one of the six eras for a writeup — span, numbers, story.

  1. GET api/v1/eras.json — the deep-dive endpoint: pick the era by id; read summary (ranks, archive-play share, busiest year, loudest/deepest tracks, top codex family), then tracks[], collaborators[], codex_families[].
  2. GET api/v1/artist.json — read eras[] for scene, releases[], note if the brief needs era color.
  3. GET api/v1/years.json — per-year transmissions, plays, top_tracks inside the span (cross-check).
  4. Match era releases against discography[] for dates, labels, links.
  5. GET api/v1/circle.json — collaborator footprints for the era's credits.

transmission-decoder

Interpret a title word through the codex: its family, its transmissions, its read.

  1. GET api/v1/codex.json — match the word against each family's words[].
  2. Read the family's epithet and its tracks[] (titles, dates, plays).
  3. Mirror decoder.html + assets/js/decoder.js matching logic.
  4. GET api/v1/sessions.json — session context for any decoded track.

network-graph-reader

Read the collaboration network: who works with whom, co-credit links, computed insights.

  1. GET api/v1/network.json — read insights first (most frequent collaborator, busiest year, first-ever).
  2. Filter edges[] on a node id for its neighborhood; kind: "co-credit" edges carry shared_tracks[].
  3. GET api/v1/circle.json — per-track detail behind each node.
  4. Report shapes, not stories: the graph records that collaborations happened, never how or why.
