✦The API playground

Touch the archive

Every record on this site is a versioned JSON document. Pick an endpoint, read the live response, copy what you need. Agents start at data/v1/index.json. The operator's manual is AGENT.md (base URL pattern, key endpoints, end-to-end workflows); the browsable agentic surface is agents.html; conventions live in API.md.

Select an endpoint to read its response.

Responses are the live files served with this page. If you opened this file directly from disk, fetching may be blocked — serve the site over HTTP instead.

deep-cuts-finder

Surface the vault's quietest-play tracks for playlists and deep listening.

  1. GET data/v1/sessions.json — flatten sessions[].tracks into one list.
  2. Sort ascending by plays; take the bottom N (median vault track ≈ 450 plays).
  3. GET data/v1/codex.json — match title words to families for a playlist theme.

session-archaeology

Reconstruct one of the 61 sessions: when it happened, what came out, who was in the room.

  1. GET data/v1/sessions.json — find the session by id; read span, tracks, plays.
  2. GET data/v1/circle.json / data/v1/scene-figures.json — resolve title credits.
  3. GET data/v1/codex.json — cross title words against the 16 families.
  4. GET data/v1/artist.json — place the session in eras[].

session-explorer

Browse all 61 sessions as a timeline: seasons, silences, deepest cuts, era/year filters.

  1. GET data/v1/session-clusters.json — read method, then insights (most prolific, longest silence, loudest/quietest sessions).
  2. Walk clusters[] for the 9 seasons and sessions[] for per-session stories (loudest, deepest_cut, cross-links).
  3. GET data/v1/sessions.json — per-session track lists for expanded cards.
  4. Mirrors sessions-explorer.html — same data, human page.

collaborator-tracer

Map a collaborator's footprint: tracks, plays, years active, verified research notes.

  1. GET data/v1/circle.json — look up the slug; read shared_transmissions, shared_plays, tracks[].
  2. If absent, GET data/v1/scene-figures.json — producers live here by rule.
  3. Read verified_notes (research pass 2026-10-11) and cite the sources.
  4. GET data/v1/artist.json — map years_active onto eras[].

milestone-watcher

Watch vault tracks approaching round-number play counts.

  1. GET data/v1/milestone-watch.json — read summit and each bands[] entry.
  2. Sort approaching tracks by needed ascending — smallest needed is closest.
  3. State the plays_snapshot date (2026-10-11) in every report.

era-briefing

Summarize one of the six eras for a writeup — span, numbers, story.

  1. GET data/v1/eras.json — the deep-dive endpoint: pick the era by id; read summary (ranks, archive-play share, busiest year, loudest/deepest tracks, top codex family), then tracks[], collaborators[], codex_families[].
  2. GET data/v1/artist.json — read eras[] for scene, releases[], note if the brief needs era color.
  3. GET data/v1/years.json — per-year transmissions, plays, top_tracks inside the span (cross-check).
  4. Match era releases against discography[] for dates, labels, links.
  5. GET data/v1/circle.json — collaborator footprints for the era's credits.

transmission-decoder

Interpret a title word through the codex: its family, its transmissions, its read.

  1. GET data/v1/codex.json — match the word against each family's words[].
  2. Read the family's epithet and its tracks[] (titles, dates, plays).
  3. Mirror decoder.html + assets/js/decoder.js matching logic.
  4. GET data/v1/sessions.json — session context for any decoded track.

network-graph-reader

Read the collaboration network: who works with whom, co-credit links, computed insights.

  1. GET data/v1/network.json — read insights first (most frequent collaborator, busiest year, first-ever).
  2. Filter edges[] on a node id for its neighborhood; kind: "co-credit" edges carry shared_tracks[].
  3. GET data/v1/circle.json — per-track detail behind each node.
  4. Report shapes, not stories: the graph records that collaborations happened, never how or why.

codex-reader

Read a codex family's full deep-dive: its decoded reading, era-by-era evolution, key sessions, voices.

  1. GET data/v1/codex-families.json — find the family by slug; read decoded first (status stated or unknown — never supply a meaning the archive doesn't claim).
  2. Walk eras[] (era evolution, deep_dive + journey links), transmissions[], key_sessions[], collaborators[].
  3. Mirrors codex/<slug>.html — same data, human page.

milestone-race-reader

Read the milestone race: approaching milestones ranked by gap-closing proximity, the 30,088-play summit chase, the record book.

  1. GET data/v1/milestone-races.json — read plays_snapshot first (2026-10-11); read pace_definition: pace_per_day is a lifetime average, and days_at_pace is plain division — an estimate, never a prediction.
  2. Walk closest_races[] (ids → play_races[]: plays, target, needed, pace), then summit_race.contenders[] (gap, catch time), session_records[], era_records[], just_crossed[].
  3. Mirrors milestone-race.html — same data, human page.

session-compare

Compare any two sessions head to head, or read the deepest-sessions ranking.

  1. GET data/v1/session-tools.json — read method + snapshot_history first (one 2026-10-11 snapshot — no play trajectories exist; play_profile is lifetime plays in upload order).
  2. Compare: pick two sessions[] profiles — tracks, plays, avg, span, era, loudest/deepest cut, collaborator overlap (only A / both / only B); deltas are B-minus-A.
  3. Deepest: quote deepest_cuts.formula (avg plays per transmission, min 2 transmissions — editorial, not an artist fact).
  4. Mirrors the compare / deepest-cuts / scrubber sections of sessions-explorer.html.

codex-pathfinder

Trace the shortest connection between any two codex figures, or read degrees of separation from Aster.

  1. GET data/v1/codex-network.json — read method first (collaborators = title-credit rule; producers = title-parsed, as credited verbatim).
  2. Path: BFS over edges[] (undirected) between node ids; report each hop with the edge label. The codex-only mode forbids the aster hub — "no path found" is a real answer for isolates.
  3. Degrees: read degrees[] — every family is 1 degree, every figure 2 via the listed carrying families; quote the via families.
  4. Mirrors the pathfinder / degrees sections of codex-network.html.
