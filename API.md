# Aster da Master — API

## Shared API conventions (all sites)
- Base: `api/v1/` relative to the site root. Works on any static host; no auth, no keys, no rate limits.
- Manifest: `api/v1/index.json` lists every endpoint with its schema URL, `updated` timestamp, and notes. Start here.
- Timestamps: ISO-8601 UTC (`2026-10-11T00:00:00Z`). Date-only fields are `YYYY-MM-DD`.
- Versions: `meta.version` semver on the manifest; breaking changes get a new `v2/` path, never a silent shape change.
- Errors: static files can't return error bodies. A missing endpoint means a wrong path — re-read `index.json`. Empty results are `[]`, never `null`. Every record carries its provenance (`source`, `observed`/`updated`).
- Pagination: not needed — payloads are complete snapshots sized for client-side filtering. If a future endpoint paginates, it will use `?page=` and document it here.
- Freshness: every payload states when it was generated and from what snapshot. Treat undated numbers as stale.

Base: `api/v1/`. Static JSON, versioned. The artist record is the single source
of truth; `data/artist.json` feeds the site renderer and mirrors it.

- `api/v1/index.json` — manifest: version, endpoints, observation date, provenance, agent routing
- `api/v1/transmission.json` — the guided-journey aggregates: six eras (2018→2026) with transmissions, plays, sessions, distributor counts, top 3 tracks (with release pages), key sessions (deep-dive links where they exist), in-era collaborators, milestones, and computed "signal" one-liners; drives `transmission.html` (schema: `api/v1/schema/transmission.json`)
- `api/v1/network.json` — the collaboration network: artist-centered graph of the 21 title-credited collaborators (from `circle.json`) + producer scene figures (from `scene-figures.json`); nodes carry track lists, dates, deterministic layout positions; edges are track-weighted, with co-credit edges for collaborators sharing a track title; computed `insights` (most frequent collaborator, producer with most credits, busiest collab year, first-ever collaborator). Generated by `scripts/build_network.py`; drives `network.html` (schema: `api/v1/schema/network.json`)
- `api/v1/eras.json` — era deep-dives: the six eras with everything `transmission.json` carries PLUS the full era transmission list (every entry, with plays + release-page link), ALL in-era collaborators (`transmission.json` keeps only the top 3), the codex families active in the era, and a computed `summary` (ranks, archive-play share, busiest year, loudest/deepest transmissions, top family). Generated by `scripts/build_eras.py` (last in the build chain — every figure recomputed and asserted); drives `eras/<id>.html` (schema: `api/v1/schema/eras.json`)
- `api/v1/artist.json` — the canonical artist record: bio, facts, discography, platforms, socials, featured release, booking
- `api/v1/codex.json` — the vocabulary codex: recurring title words grouped into 16 named families, with per-track lists (computed at build time by `scripts/build_codex.py` from `data/artist.json`)
- `api/v1/schema/artist.json` — JSON Schema (draft-07) for the artist record
- `api/v1/schema/codex.json` — JSON Schema (draft-07) for the codex

## Publication rule

`research_status` gates everything. While it reads `PENDING`, no artist facts
are published — the site renders its designed "assembling the archive" state.
Facts enter only from verified public platform pages (Spotify, Apple Music,
SoundCloud, YouTube, etc.). Unverified claims are never published; identity
drift (a platform URL pointing at a different artist) escalates to research.

## Cover art

Discography entries carry an `artwork` URL sourced from the iTunes Search API
(`artworkUrl100`, upgraded to 600×600 via Apple's standard size pattern) and
hotlinked from Apple's CDN (`*.mzstatic.com`). Verified 2026-10-11: all 34
release artworks resolve with `image/*` content types. The site renders them
with `loading="lazy"` and falls back to a monogram tile if a URL ever dies.
Releases with no artwork simply omit the field — no placeholders.

## Provenance

Every discography entry carries a `source` string naming the platform/profile
the record came from and the verification date. All 34 distributor releases:
`Apple Music profile 1466301103 ("Aster Da Master") · iTunes Search API primary
metadata · verified 2026-10-11`. The site renders this as a small provenance
line on every discography card and in each release page's Provenance block.

## SoundCloud vault

`type: "SoundCloud-only"` marks tracks from the official SoundCloud profile
(https://soundcloud.com/asterdamaster), not distributor metadata. The full
catalog was verified 2026-10-11 via a read-only live-browser pass: **185
tracks** (2018:39 / 2019:36 / 2020:15 / 2021:13 / 2022:12 / 2023:26 /
2024:20 / 2025:17 / 2026:7), each with title, upload date, and a play-count
snapshot (play counts drift over time; the capture date is stated on every
page). Per-track SoundCloud URLs are not published (slugs not resolved by the
capture); every vault entry links the official profile. The top-level
`vault` object carries the profile facts (display name, followers, location,
bio) and capture date. The bio line "somelowlifes / Litemode Trilogy OTW" is
recorded under top-level `upcoming` as teased-not-confirmed. Vault entries
never carry lyrics — titles only.

and `tracks.json` (the captured catalog).

## Release pages & press kit

- `releases/` — one static page per release, generated by
  `scripts/build_releases.py` from `data/artist.json` (re-run after data
  changes). Each page: cover art, type, date, label, track count, credits as
  listed in the title, platform links, and a provenance block. `releases/index.html`
  filters by year, type, and label.
- `press-kit.html` — one-page press kit rendered from the API data (stats,
  featured release, eras, platforms, collaborators, verified-facts-vs-unknowns
  box) with `@media print` styling for clean printing / PDF export.

## Numbers & Codex

- The homepage's **Numbers** section (VIII) is a live stats dashboard computed
  client-side from `data/artist.json`: total SoundCloud plays (257,394 as of the
  2026-10-11 snapshot), plays/tracks by year, top 10 tracks by plays, and
  collaborator frequency parsed from `w/`/`ft.` title credits.
- The **Codex** section (IX) renders `data/codex.json`, built by
  `scripts/build_codex.py` (re-run after data changes): 16 vocabulary families
  (Modes, Castings, Keys, Vessels, Rites, Light, Dark...) with per-track lists.
  Method: word-boundary matching over leet-normalized titles; every claim is a
  count — no meanings invented.
- The **Deep cuts** section (X) spotlights the 15 lowest-play vault tracks
  (plays > 0, uploaded before 2025) — computed client-side, "the buried
  transmissions."
- `timeline.html` — interactive career timeline 2018–2026: every transmission
  plotted client-side from `data/artist.json`; distributor releases ride a gold
  lane, vault tracks burn neon with height by log play count; era bands from the
  Eras data; year-zoom buttons; hover/focus/tap tooltips; per-year summary list.
- `network.html` — collaboration network: interactive SVG graph driven by
  `api/v1/network.json` (generated by `scripts/build_network.py` — the single
  source of truth; the page renders, never computes). Artist at center; 21
  title-credited collaborator nodes sized by shared tracks; producer scene
  figures as squares; track-weighted edges plus co-credit edges for
  collaborators sharing a track title. Draggable nodes, click/Enter side panel
  (tracks together, first/last dates, circle-page link, co-credit links),
  arrow-key node navigation, era slider (2018–2026 highlight), producers
  toggle, name search; the same data as an accessible table; computed insights
  bar (most frequent collaborator, producer with most credits, busiest collab
  year, first-ever collaborator).

## Search, on-this-day, era intelligence, cast lots (v0.7.0)

- **Global search** (`assets/js/search.js`, overlay on index/timeline/network/
  press-kit): searches transmissions (deep-links to `releases/<slug>.html` via
  `api/v1/release-slugs.json`), collaborators, codex families, and eras.
  `/` opens, `Esc` closes, arrows + `Enter` navigate, `aria-activedescendant`
  focus management. Slugs generated by `scripts/build_search_index.py` with the
  exact dedup logic of `scripts/build_releases.py` — re-run after data changes.
- **On this day** (homepage XI + `api/v1/on-this-day.json`): `"MM-DD"` keys map
  to the tracks uploaded/released on that month-day across all years, with title,
  date, plays, type, and release-page path. The homepage section reads the API
  and renders "the calendar remembers" — empty days are stated, not filled.

## Year-in-review archive, method, trilogy watch (v0.7.1)

- `years/2018.html` … `years/2026.html` + `years/index.html` — the yearly
  archive, generated by `scripts/build_years.py` from `data/artist.json`
  (re-run after data changes). Per year: transmission count, total vault plays,
  top-10 tracks by plays, key collaborators (parsed from title credits), the
  era it belongs to, 3 "defining tracks" (top by plays — labeled a data pick,
  not an editorial one), and the full chronological transmission list deep-
  linking to `releases/<slug>.html` (slug logic imported from
  `scripts/build_releases.py`, the single source of truth).
- `api/v1/years.json` — machine-readable per-year stats, registered in
  `api/v1/index.json` endpoints.
- `method.html` — the credibility backbone: research passes and dates,
  identity resolution (the two Apple profiles, the artist-linked Spotify, the
  excluded Asters), confidence flags (verified / single-source / uncertain /
  unknown), the ritual-voice-is-presentation note, the no-lyrics policy, and
  how to report corrections.
- `trilogy.html` — the Litemode Trilogy watch: the bio line quoted verbatim,
  related vocabulary counts from the data (not confirmation), the bar for
  confirmation, and an explicit "nothing confirmed as of 2026-10-11" stamp.
  Never speculates; updates only on real signals.
- **Era intelligence**: each era card (VII) now carries an expandable deep-dive
  computed client-side from the archive — transmission count, total plays, top 5
  by plays, key collaborators of the span. Play counts are vault-only (snapshot
  2026-10-11); distributor releases have no per-track play data.
- **Cast lots** (homepage XII): "Summon a random transmission" draws one blind
  vault track (title, upload date, plays) with a SoundCloud link and re-summon;
  `aria-live` result region.

  plays, plus the codex family claiming the word (linked). Supports `?w=word`
  deep links. Titles only — no lyrics live here.
