The agentic surface

This archive is built to be read by machines as well as people. Everything below is stable, versioned, and reachable as plain files — no keys, no sessions, no scraping. Start at api/v1/index.json; it names every endpoint and carries the data version.

Search index

The site's search overlay (/) is a client-side fetch over the API — no server, no index build on your side. To replicate it, fetch and filter locally:

  • api/v1/release-slugs.json — every transmission title → its release page (the overlay's primary corpus).
  • api/v1/circle.json — collaborator names and pages.
  • api/v1/codex.json — the 16 family names and their words.
  • api/v1/artist.json → eras[] — era names and spans.

The reference implementation is assets/js/search.js (collaborator parsing included).

Rates & expectations

  • Static files, no auth, no rate limits. This is a static site — the whole API is files on disk. Fetch freely, but serve over HTTP: browsers block fetch() from file:// pages.
  • Sizes are small. Largest endpoints: artist.json (~155 KB), sessions.json (~50 KB), on-this-day.json (~40 KB). Everything else is under 16 KB. Cache aggressively; check index.json → version (currently 0.17.0) to invalidate.
  • Play counts are a snapshot. SoundCloud plays were captured read-only on 2026-10-11 (plays_snapshot / observed fields). They drift daily — always state the snapshot date, never present them as live.
  • Upload dates ≠ recording dates. Sessions are computed clusters (7-day upload-gap rule), not artist-named studio sessions.
  • The rules of the archive: titles and metadata only — never lyrics; never invent biography; unknowns are listed as unknowns (method.html → "The unknowns register"); the circle is title-credit only (producers live in scene-figures.json).

Four worked agent workflows

1. Write a 500-word era briefing

Skill: era-briefing

  1. GET api/v1/index.json — confirm version, note observed.
  2. GET api/v1/eras.json — pick the era by id; read summary first (ranks, archive-play share, busiest year, loudest/deepest tracks, top codex family), then tracks[], collaborators[], codex_families[].
  3. GET api/v1/artist.json — read eras[], pick the era (e.g. "The First Rite", span 2017–2019). Capture scene, releases[], note.
  4. GET api/v1/years.json — for each year in the span, pull transmissions, plays, and top_tracks (e.g. 2018: 39 transmissions, 104,479 plays).
  5. Match the era's releases[] titles against discography[] for dates, labels, and platform links.
  6. Scan the era's top tracks for ft./w/ credits; GET api/v1/circle.json for each collaborator's footprint.
  7. Write three moves — the span, the numbers, the story — every sentence tracing to an endpoint field. Close with the archive's own framing ("The Silence": no releases found in 2025; the reason is unknown and not speculated here).

2. Find 10 deep cuts for a playlist

Skill: deep-cuts-finder

  1. GET api/v1/sessions.json — flatten sessions[].tracks into one list of {title, date, plays, page}.
  2. Sort ascending by plays. (Median vault track ≈ 450 plays — anything far below is a genuine deep cut.)
  3. Take the bottom 10. Example bottom five: "nitemode2019 w/ Max+Vetty prod. NaXi.wav" (17 plays), "No Puppets A11owed prod. xtasane" (24), "Im tha Bouncerrr prod. sustain" (28), "For Brian (Neck Deep) outro [produced by AWFL]" (43), "6 stop telling myself i'm not" (46).
  4. GET api/v1/codex.json — match title words to families for a playlist theme (e.g. several picks carry "The Modes" words).
  5. Present title, plays, date, and one line on why each qualifies. Quote titles verbatim; never quote lyrics.

3. Trace a collaborator

Skill: collaborator-tracer

  1. GET api/v1/circle.json — look up the slug (e.g. capoxxo). Read shared_transmissions (2), shared_plays (16,174), years_active ("2019"), and each track's date and plays.
  2. If the slug is absent, GET api/v1/scene-figures.json — producers are excluded from the circle by rule (e.g. Fish Narc lives here with facts and sources).
  3. Read verified_notes (research pass 2026-10-11): capoxxo — Pitchfork's hyperpop-digicore canon; Persona tape w/ mayh3mp (Cult Love Sound Tapes, 2022).
  4. GET api/v1/artist.json — map the collaborator's years onto eras[] (capoxxo's 2019 tracks sit in "The First Rite").
  5. Summarize: who, footprint, the tracks in order, the verified research (cited), the era position. Never invent how they met.

4. Deep-dive one era

Skill: era-briefing

  1. GET api/v1/eras.json — pick the era by id (e.g. the-somelowlifes-era). One file answers the whole brief: summary, tracks[], collaborators[] (every in-era voice — transmission.json keeps only the top 3), codex_families[], key_sessions[], milestones[].
  2. Read summary first — every figure is recomputed and asserted by scripts/build_eras.py. Example, The SomeLowLifes Era: rank #2 of 6 by transmissions (58) and by plays (14,982 — 5.82% of the archive); busiest year 2023 (31 transmissions, 10,179 plays); loudest "Clock In The Benz w/ Lil Yu prod shinju" (725 plays); deepest cut "nitemode2019 w/ Max+Vetty prod. NaXi.wav" (17 plays); top codex family "The Rites" (7 transmissions, 2,243 plays); 5 collaborators carrying 8.5% of the era's plays; 3 milestones.
  3. Walk tracks[] for the full transmission list (every entry with release-page link; distributor releases carry no vault play count).
  4. Pitfall check: play counts are the 2026-10-11 snapshot; upload dates ≠ recording dates. Never quote or reproduce lyrics — titles and metadata only.
